# maxima consulting — инструкция по веб-версии

Веб-приложение для автоматизации консалтингового цикла: **загрузка документов клиента → выбор услуги → AI-анализ → отчёт → история и экспорт**.

Стек: **FastAPI** (бэкенд) + **React / Vite** (фронтенд) + **Anthropic Claude** (генерация отчётов).

---

## 1. Что делает веб-версия

| Этап | Описание |
|------|----------|
| Авторизация | JWT, роли сотрудников (не клиентов) |
| Загрузка данных | Несколько файлов клиента за один анализ |
| AI-анализ | Потоковая генерация отчёта (SSE) по выбранной услуге |
| Сохранение | Отчёты в папку `reports/` в формате Markdown |
| История | Просмотр, фильтры по клиенту и услуге, скачивание MD/PDF |
| Админка | Управление пользователями (только роль `admin`) |

CLI-версия (`consulting_agent.py`) описана в корневом `README.md`. Веб-версия использует те же навыки (`skills/`) и `.env`.

## 2. Требования

- **Python** 3.10+
- **Node.js** 18+ и **npm**

- Frontend: `http://localhost:5173`

## 3. Первичная установка

Все команды — из корня проекта `consulting-agent/`.

### 3.1. Python-зависимости

```bash
python3 -m pip install -r requirements.txt
python3 -m pip install -r web/backend/requirements-web.txt
```

### 3.2. Node-зависимости

```bash
cd web/frontend
npm install
cd ../..
```

### 3.3. Переменные окружения

```bash
cp .env.example .env
```

Откройте `.env` и укажите ключ API:

```env
ANTHROPIC_API_KEY=sk-ant-...
DEFAULT_MODEL=claude-sonnet-4-6
FALLBACK_MODEL=claude-haiku-4-5-20251001
MAX_TOKENS=16000
CONSULTANT_NAME=Максим Зугров
CONSULTANT_PHONE=+79106407686
COMPANY_NAME=Максима Консалтинг
```

| Переменная | Назначение |
|------------|------------|
| `ANTHROPIC_API_KEY` | Ключ Anthropic (обязательно) |
| `DEFAULT_MODEL` | Основная модель для отчётов |
| `MAX_TOKENS` | Лимит длины ответа (рекомендуется 16000 для полных отчётов) |
| `CONSULTANT_NAME` | Имя консультанта в системном промпте |
| `CONSULTANT_PHONE` | Контакт в отчётах |
| `COMPANY_NAME` | Название компании в промпте |

## 4. Запуск

### Быстрый запуск (рекомендуется)

```bash
cd web
chmod +x start.sh
./start.sh
```

Откройте в браузере: **http://localhost:5173**

Остановка: `Ctrl+C` в терминале.

### Ручной запуск (два терминала)

**Терминал 1 — бэкенд:**

```bash
cd web/backend
PYTHONPATH=. python3 -m uvicorn main:app --reload --port 8000
```

**Терминал 2 — фронтенд:**

```bash
cd web/frontend
npm run dev
```

### Проверка, что всё работает

```bash
curl http://localhost:8000/api/health
# {"status":"ok"}
```

## 5. Вход и роли

Пользователи — **сотрудники** maxima consulting, не клиенты.

| Роль | Возможности |
|------|-------------|
| `admin` | Всё + раздел «Пользователи» |
| `analyst` | Загрузка файлов, запуск анализа, сохранение отчётов |
| `viewer` | Только просмотр истории (анализ запустить нельзя) |

### Тестовые учётные записи (по умолчанию)

| Email | Пароль | Роль |
|-------|--------|------|
| `admin@maximaconsult.ru` | `admin123` | admin |
| `analyst@maximaconsult.ru` | `analyst123` | analyst |

Файл пользователей: `web/backend/data/users.json`.  
Новых сотрудников добавляйте через UI (раздел **Пользователи**) или правкой JSON с bcrypt-хешем пароля.

> **Важно:** смените пароли перед использованием вне локальной разработки.

## 6. Рабочий процесс анализа

1. Войти под `admin` или `analyst`.
2. Перейти в **Новый анализ**.
3. **Шаг 1 — Документы:** перетащить или выбрать один или несколько файлов. Можно добавлять файлы повторно.
4. **Шаг 2 — Услуга:** выбрать услугу, указать название клиента и опциональный контекст.
5. Нажать **Запустить анализ** — отчёт появится потоком в реальном времени.
6. После завершения:
   - **⬇ MD** — скачать Markdown локально;
   - **⬇ PDF** — экспорт через браузер (html2canvas + jsPDF);
   - **💾 Сохранить** — записать в историю (`reports/`).

## 12. API (кратко)

| Метод | Путь | Назначение |
|-------|------|------------|
| POST | `/api/auth/login` | Вход, получение JWT |
| GET | `/api/auth/me` | Текущий пользователь |
| GET | `/api/services` | Список услуг |
| POST | `/api/analyze` | Анализ (multipart: `files`, `service_code`, `client_name`, `context`) |
| GET | `/api/reports` | Список отчётов |
| GET | `/api/reports/{filename}` | Содержимое отчёта |
| GET | `/api/reports/{filename}/download` | Скачивание MD |
| POST | `/api/reports` | Сохранение отчёта |

Все защищённые маршруты требуют заголовок:  
`Authorization: Bearer <token>`

## 13. Типичные проблемы

### «Не удаётся войти» / ECONNREFUSED

Бэкенд не запущен. Проверьте:

```bash
curl http://localhost:8000/api/health
```

Запустите `./start.sh` или uvicorn вручную.

### Ошибка 500 при анализе

- Проверьте `ANTHROPIC_API_KEY` в `.env`.
- Перезапустите бэкенд после изменения `.env`.
- Смотрите логи uvicorn в терминале.

### Отчёт обрывается на середине

Увеличьте `MAX_TOKENS` в `.env` (рекомендуется `16000`).

### Услуги «не работают» / пустой отчёт

Убедитесь, что в `skills/` есть `.md` для выбранной услуги (см. таблицу в разделе 7).

### `uvicorn: command not found`

Используйте:

```bash
python3 -m uvicorn main:app --reload --port 8000
```

### `ModuleNotFoundError: bcrypt` (или другой модуль)

```bash
python3 -m pip install -r web/backend/requirements-web.txt
```

### Фильтр по услуге пустой для старых отчётов

Старые файлы без разделителя `--` в имени могут некорректно определять услугу. Новые отчёты сохраняются в формате `клиент--услуга.md`.

## 16. Связь с CLI

| CLI | Веб |
|-----|-----|
| `python consulting_agent.py analyze` | Раздел «Новый анализ» |
| `python consulting_agent.py list-reports` | Раздел «История отчётов» |
| `--service N` | Выбор карточки услуги |
| `--file` | Загрузка через UI |

Оба режима пишут отчёты в одну папку `reports/` и используют одни и те же `skills/`.
